## 运行离线测试

在普通本地文件夹准备 Python 3.12 环境和依赖，运行素材下载脚本后，在项目根目录执行：

```bash
QT_QPA_PLATFORM=offscreen \
BAILONG_DATA_DIR="$PWD/build/test-state" \
.venv/bin/python -m unittest discover -s app -p 'test_*.py' -v
```

`BAILONG_DATA_DIR` 将测试产生的本机数据隔离到构建目录。离线测试不发送真实聊天任务，使用模拟结果验证额度解析、对话与审批界面。

## 打包应用自检

完成构建后，执行：

```bash
BAILONG_DATA_DIR="$PWD/build/selftest-state" \
dist/BailongPet.app/Contents/MacOS/BailongPet --self-test
```

检查 `build/selftest-state/检查报告.json` 中的 `passed`。该自检检查动画、界面与模拟交互，不证明真实网络连接或原生桌面上的完整行为。

只读额度检查必须在已经安装并登录 Codex 的普通用户会话中单独运行：

```bash
BAILONG_DATA_DIR="$PWD/build/quota-test-state" \
dist/BailongPet.app/Contents/MacOS/BailongPet --self-test --quota-only
```

报告只记录是否成功及返回窗口数，不写入账号、凭证或额度数值。不要把额度自检的网络失败当作所有离线功能失败。

`--chat-only` 会发送真实对话任务并使用自己的额度，不属于默认离线验收；仅在明确决定进行在线任务验收时使用。

## 桌面检查

启动应用后，切换到其他应用，确认桌宠仍留在当前桌面；然后检查单击、拖动/落地、右键菜单、隐藏/菜单栏唤回。原生诊断中的 `isOnActiveSpace` 和 `hidesOnDeactivate` 可以协助排错，但不能替代实际观察和鼠标交互。

如果源代码测试报告找不到 Qt 平台插件，而插件文件确实存在，请先检查云盘文件提供器是否给 Qt 插件附加了隐藏标记。建议移至普通本地目录；构建脚本已处理构建依赖和输出应用的相关文件标记。不要把某台机器的临时插件目录写进项目或 CI 配置。

源码、Git 历史和发布附件应排除构建目录、个人数据、日志和凭证。当前 `.gitignore` 已覆盖已知生成目录；发布前仍应按实际文件清单检查。
